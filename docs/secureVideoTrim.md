# 多租户视频裁剪：隔离执行设计（未上线）

现状：视频节点使用 `/api/ffmpeg/execute`。多租户客户被权限中间件拒绝，隔离 HTTP 已复现 403。该接口支持通用 FFmpeg 命令，不能为修复裁剪而直接开放。

## 客户接口

仅提供专用 `POST /api/ffmpeg/trim`，字段为工作区、源视频相对路径、开始秒数和结束秒数；拒绝额外字段、URL、任意编码器或参数。仅在执行隔离与验证通过后放行此精确方法和路径。身份来自已认证会话，服务端调用现有工作区授权，不能使用客户端账号 ID。

服务端约束输入为普通 MP4/MOV：尺寸不超过 512 MiB、时长不超过 120 秒，有限起止数值满足 `0 ≤ start < end ≤ duration`；限制分辨率、帧率及最大片段长度。输出由服务端生成不可预测 UUID，独占创建且不能覆盖原文件。只接受固定版本封装与输出格式，不把用户输入拼入命令行或滤镜。

## 文件和隔离边界

- 校验工作区后，对源文件使用无符号链接跟随的打开方式；验证文件类型、大小、硬链接策略及打开后的句柄实际归属。Linux 可对 `/proc/self/fd/<fd>` 做归属检查，并通过文件描述符传递源数据。仅重新检查路径或进程内锁不足以防跨实例替换。
- 作业执行器使用独立的最小权限容器或等价强隔离：无网络、非 root、只读根、丢弃全部 capabilities、禁止提权、固定 seccomp，并限制 CPU、内存、进程数及墙钟时间。普通应用容器的只读根和 capability 限制不等于 FFmpeg 子进程已隔离。
- 应用不得持有 Docker 管理 socket。受信任的独立作业管理器接收带界限的数据流和经认证的任务请求，只运行固定镜像与固定参数；不能接收宿主路径、网络地址、可执行文件或任意选项。每个作业只得到自己的只读输入和独占、有限空间的输出；不得挂载其他客户工作区、数据库或密钥。
- FFmpeg 固定使用 `-nostdin`，ffprobe 使用关闭的标准输入（不假设 ffprobe 支持 `-nostdin`）；两者固定 MOV demuxer、`file` 协议白名单、关闭外部数据引用及绝对外链，输出强制无覆盖并限制线程数。这些参数是纵深防御，不代替操作系统隔离。
- 发布结果时使用受保护的目录句柄及 `O_EXCL`/不跟随符号链接，确认仍位于同一授权工作区；不得只在打开前执行一次 realpath。输出须经独立探测确认非空、视频流存在、大小及所选时长在容差内；`-fs` 截断即使退出码为零也不能当成功。

## 并发、取消与空间

全局并发槽必须由作业管理器持有至沙箱进程实际退出并被回收。数据库租约过期不能证明旧 FFmpeg 已停止；状态未知时不释放槽位。服务进程崩溃后由管理器终止并确认回收，无法确认则保持阻塞并报警。限制每账号并发，防止多实例绕过；多实例只在共享一致的协调存储下启用。

恢复能力必须与应用请求使用不同的运维 socket、身份和凭据，并持久绑定作业、应用实例和容器 ID。先单独创建容器并在获得不可变 ID 后持久化，再启动；创建请求状态不明时禁止仅凭 CLI 进程消失或一次容器列表为空推断安全。恢复需验证旧应用实例与卷写入已经实际隔离，互斥覆盖证明读取与释放全过程，并用作业身份和代次比较锁所有权，不能盲删固定锁目录。目录不存在检查到额度释放之间也须保持隔离屏障。当前恢复原型因上述屏障未完成而硬关闭。

输入副本、输出和工作区最终文件的峰值空间必须在写入前预留，结合真实磁盘可用空间水位。上限以输出可能字节和双份文件同时存在的峰值计算；每次写入设硬上限。取消或超时时先停止并确认沙箱退出，未确认退出之前不允许重新占用槽位。失败、中断和身份变化均保留不确定产物，不自动删除线上文件或记录；后续仅对有明确授权及所有权证明的对象进行清理和对账。

## 验收门槛

1. 用独立客户、独立工作区和合成视频在 staging 完整走节点选择、拖动时间、执行、生成新节点和回放；不调用付费模型。
2. HTTP 验证未登录、其他账号工作区、编码路径、符号链接替换、硬链接、外链媒体、非法时间和超限输入均拒绝，原文件不变，现有输出不被覆盖；通用 `/api/ffmpeg/execute` 对客户继续拒绝。
3. 跨进程并发、作业管理器或应用中止、租约到期、子进程未退出、磁盘不足和输出截断逐项验证：始终限制真实执行进程和总占用，失败保留可追溯状态。
4. 在真实 staging 运行环境证明容器无网络、无特权、无密钥和其他用户文件访问，并核对 CPU、内存、PID 和时间上限；独立安全复审通过后才能开放路由。

## 故障降级与备份边界（待隔离环境验收）

`TOONFLOW_SECURE_TRIM_READ_ONLY=1` 优先于裁剪启用开关：新裁剪、未确认任务的自动恢复及释放操作均关闭；只读查询允许确认已经完成的任务，当前兼容版本仍可读取和导出这些私有素材。此模式仍依赖受控存储、原配额服务、单实例锁和原数据库；任一组件不可用时拒绝访问，不能将读失败当成普通文件不存在。它是故障隔离措施，并不等于回退到旧镜像。旧镜像不认识裁剪账本和私有素材，不能在存在裁剪数据时直接替换。

完整备份须覆盖同一一致性时点的应用数据卷、用户工作区、`projectQuota/privateTrim`、账号及任务 SQLite 数据与 WAL、项目配额注册表和裁剪工作进程状态，并保留 UID/GID、模式及 ext4 project ID/继承属性。停止并阻断全部应用、存储服务、配额 helper、裁剪管理器及自动重启，确认没有活动或状态不明的裁剪进程后，才可在隔离副本上制作与验证快照；不能仅复制 SQLite 主文件或仅导出项目 ZIP。恢复须在独立卷完成项目配额和所有权校验，再用合成账号读取画布、素材、归档记录和配额，确认无误后才能考虑替换。上述条件尚未形成已验证的自动备份/旧版迁移工具，不得直接用于客户卷。
